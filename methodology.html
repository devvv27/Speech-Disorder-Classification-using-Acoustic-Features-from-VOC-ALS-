Methodology: ALS Speech Disorder Classification

Concise summary of how data is processed, features are extracted, models are trained, and how the deployed web app performs real-time inference.

1. Objective and Data

The goal is to classify speech recordings as ALS or HC using acoustic features. The training data is stored in voc_als_acoustic_features_mapped.csv, and only numeric acoustic columns are used for modeling.

Task: Binary classification Input: Original WAV Output: Class + probability Deployment: Flask web app

2. Signal and Feature Logic

The extractor uses both the original and voiced-only versions of each file to compute complementary features.

  • Original WAV: MFCC and MFCC-delta summaries.
  • Voiced WAV (_OnlyVoiced): F0, formants, jitter, shimmer, HNR, intensity, and complexity features.
  • This matches the training-time feature extraction rule.

3. Voiced Segmentation and Extraction Pipeline

For each uploaded original WAV, Praat scripts are run via Parselmouth to generate voiced/<name>_OnlyVoiced.wav, then the canonical extractor computes the final feature row.

Step 1: Upload original .wav.
Step 2: Create voiced file with textgrid2py.praat + extract_voiced_segments.praat.
Step 3: Extract acoustic features using extract_features.py.
Step 4: Clean/reindex feature vector for model input.

4. Models Trained and Selected

Three baseline models were trained with standardized numeric features and an 80/20 stratified split: Logistic Regression, SVM (RBF), and Random Forest.

Model Accuracy Weighted F1
Logistic Regression 0.7778 0.7797
Random Forest 0.7516 0.7324
SVM (RBF) 0.7451 0.7176
Logistic Regression is currently the deployed model in the web application.

5. Web Application Workflow

The Flask app receives an original WAV at /predict, extracts features with the same pipeline, scales to training schema, and predicts using logistic_regression_model.pkl.

1. Upload original .wav.
2. Create voiced file and extract full feature vector.
3. Reindex and standardize features.
4. Return prediction, probabilities, and confidence.

Operational Note

  • If voiced extraction fails, the app may use fallback behavior; API response includes fallback_used.
  • Debug mode (debug=1) can expose extracted features for parity checks.

6. Short Conclusion

In summary, this project uses a consistent extraction strategy (original + voiced signals), compares three baseline classifiers, and deploys Logistic Regression for real-time inference through a Flask web interface.
